Catálogo completo de las 173 pantallas registradas en `pages/ScreenExplorer.tsx`, con su archivo real, el nombre de ruta usado en `App.tsx`, el nombre visible en pantalla, las APIs/endpoints que consume hoy, y con qué parte del backend Laravel (`C:\Users\hamza\Desktop\PROYECTOS\APP\mightyfitness\fitness-backend`) está o debería estar conectada.

> **Nota (2026-08-13)**: 4 filas de este catálogo ya no existen — `Payment`, `Payment Scheduled` y `Choose Plan` (además de `Subscribe`, no listada aquí) se **borraron por completo** al quitar la compra dentro de la app (Apple/Google exigen que la app no venda contenido digital dentro sin su propio IAP; la compra pasa a ser 100% externa). Ver `docs/TAREAS.md` para el detalle del cambio.
>
> **Nota (2026-08-23)**: la fila `Onboarding Complete` (`MigratedOnboardingComplete`/`onboarding_complete_screen.tsx`) ya no existe — pedido explícito del usuario, era un paso intermedio innecesario tras el onboarding. Su lógica (`completeOnboarding()`) se movió al botón final de `MigratedAssessmentResult`. Ver `docs/TAREAS.md`.

## Cómo se generó este documento

Para cada pantalla se localizó su registro (`<Stack.Screen>` / `<Tab.Screen>` / `<MStack.Screen>`) en `App.tsx`, se resolvió el archivo real del componente, se leyó el código para determinar el texto visible en pantalla y las llamadas a API existentes, y se cruzó cada endpoint contra `routes/api.php` y los controladores en `app/Http/Controllers/API/` del backend para confirmar (o sugerir) el módulo correspondiente.

## Leyenda de la columna "APIs/Endpoints usados"

- **`MÉTODO endpoint`** — llamada real y funcional en el código actual.
- **"Ninguna (estática/local)"** — la pantalla no llama a ningún backend; usa datos hardcodeados, mock, o AsyncStorage local. Incluye casos donde la llamada existe en el código pero está **comentada** (dejada como placeholder por el desarrollador original).
- **"Ninguna (recibe datos por params)"** — la pantalla no hace fetch propio porque recibe todo el contenido ya cargado vía `route.params` desde la pantalla anterior.

## Leyenda de la columna "Módulo backend"

- Nombre de controlador sin prefijo — el endpoint ya está conectado y funcionando.
- **"Sugerido: ..."** — la pantalla no tiene esa API conectada todavía, pero existe (o debería existir) un endpoint candidato razonable en el backend, indicado con su controlador exacto.
- **"N/A (no requiere backend)"** — pantalla puramente de navegación/UI, o funcionalidad (ej. emparejamiento Bluetooth con wearables) sin contraparte en el backend actual.

## Hallazgos transversales (resumen ejecutivo)

Patrones repetidos detectados across todas las pantallas migradas, útiles como punto de partida para priorizar trabajo de conexión API:

1. **Módulos de API ya existentes pero nunca importados en sus pantallas**: `api/subscription.ts` está completo y funcional (`getPackageList`, `subscribe`, `getSubscriptionPlanList`, `cancel`, `getPaymentGateways`) pero **ninguna** de las 4 pantallas de pago/suscripción (Subscribe, Subscription Detail, Payment, Payment Scheduled) lo usa — todas tienen la llamada comentada.
2. **Llamadas API "fantasma" (comentadas como placeholder)**: patrón repetido `// const value = await xApi(...)` en pantallas de recordatorios de salud (agua, comidas), OTP/login social, horarios de clase (`Schedule`), y varias más. En todos estos casos el endpoint real ya existe en `routes/api.php`; solo falta descomentar y adaptar la llamada.
3. **Stubs locales que imitan una API pero no llaman a nada real**: `search_screen.tsx` (exercises) y las 4 pantallas de `recipe_*_screen.tsx` (Recipe Main, Recipe List V2, Recipe Category List, Recipe Tag List) definen sus propias funciones `getXApi` que devuelven arrays vacíos o datos mock, ignorando el módulo real `api/exercises.ts` / `api/recipes.ts`.
4. **Botones que deberían llamar a una API existente y no lo hacen**: `post_details_screen.tsx` — like/bookmark solo cambian estado local en React pese a que `postsApi.like`/`postsApi.bookmark` ya existen y funcionan.
5. ~~**Endpoint conectado pero semánticamente incorrecto**: `exercise_history_screen.tsx` llama a `exercisesApi.getList` (catálogo general)~~ — **Corregido**: ahora llama a `exercisesApi.getUserExercises` (`GET get-user-exercise`, `ExerciseController::getUserExercise` — historial real de ejercicios registrados sueltos, `UserExercise` con `workout_id`/`workout_day_id` nulos), no al catálogo general ni a `GET exercise-history`.
6. **Sin contraparte en el backend actual**: pantallas de video (Video Screen/Detail, YouTube Player, Chewie Player) — no existe ningún módulo de vídeo en `routes/api.php`. Igual para el flujo de emparejamiento de wearables (Emparejando, Device Connected, Link Device Choice/List) — no hay endpoints de "device pairing" en el backend.
7. **"Home Modern" (`pages/migrated/home_screen_modern.tsx`, ruta `MigratedHomeModern`) es la pantalla de inicio real de la app** desde el cambio reciente: la ruta `HomePage` del tab principal renderiza `MigratedNavigator`, cuyo `initialRouteName` es `MigratedHomeModern`. El componente original `pages/Home.tsx` sigue en el repo pero ya no está conectado a ninguna ruta activa.
8. **"Home Modern V2" (`pages/migrated/home_screen_modern_v2.tsx`, ruta `MigratedHomeModernV2`, 2026-08-19)**: copia de Home Modern con cabecera rediseñada (gradiente, saludo dinámico, anillos Recovery/Strain placeholder, banner condicional, frase motivacional contextual — ver `docs/TAREAS.md` entrada del 2026-08-19). Todavía **no** es la ruta de inicio real — solo alcanzable vía `ScreenExplorer` ("Home Modern V2 (nueva cabecera)"). Pendiente decisión de si sustituye a `MigratedHomeModern`.

## Notas

1. **Home / HomePage**: la ruta `Home` del stack raíz renderiza `Homenavigator` (bottom tabs), cuyo tab inicial `HomePage` apunta al componente `MigratedNavigator` (definido inline en `App.tsx`, líneas 428-577), y este a su vez usa `MigratedHomeModern` como `initialRouteName`, que renderiza el componente `HomeScreenModern` importado desde `@pages/migrated/home_screen_modern` (`pages/migrated/home_screen_modern.tsx`). El componente original `pages/Home.tsx` (importado en `App.tsx` línea 15 como `Home`) sigue existiendo en el repo pero **no está conectado a ninguna ruta activa** — el import `Home` de `@pages/Home` no se usa en ningún `<Stack.Screen>` ni `<Tab.Screen>` del árbol de navegación actual.
2. El título visible de Home es dinámico: `"Hola, {displayName}!"` (línea 240 de `home_screen_modern.tsx`), tomado de `useAuth().state.user`.
3. Varias pantallas de auth reciben la llamada API indirectamente a través del hook `useAuth()` (definido en `store/AuthContext.tsx`), que internamente invoca `authApi.login` / `authApi.register`. Esto se documentó igualmente porque es el flujo real de datos de la pantalla.
4. Pantallas sin ninguna certeza relevante: ninguna quedó sin determinar — todas las 34 pantallas del lote fueron abiertas y verificadas directamente (título visible + llamadas API o ausencia de ellas).
